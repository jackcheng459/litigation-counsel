# Litigation Counsel

当前版本：1.0.0

面向 2 至 3 人小型律师协作团队的民商事诉讼专家。它按案件当前程序阶段处理材料，建立争点、要件、事实与证据映射，协助形成诉讼策略、文书、庭审准备和调解评估的候选底稿。

本专家不替律师确认案件事实、法律期限、诉讼请求、程序策略、金额口径、和解底线或对外签发。

## 可以直接怎样说

### 1. 案件初步分析

`请基于本轮已授权的材料，先区分原件支持的事实、当事人陈述、待核事项和证据缺口，再形成争点与策略草案。`

### 2. 原告方诉前评估

`请检查主体、管辖、请求、要件、证据和可能抗辩。法源或送达材料未核验时保留待核状态，不要替我决定是否起诉。`

### 3. 被告方应诉准备

`请把对方每项请求拆解为要件，对照现有证据、我方回应、对方可能补强点和待核法源，形成答辩策略草案。`

### 4. 证据体系与缺口

`请建立争点、要件、事实和证据矩阵，分别说明每份证据能证明什么、不能证明什么、冲突与补强动作。`

### 5. 文书起草

`请在完成事实证据映射和法源状态表后，起草答辩状工作稿。无依据的事实不得写成已证实，未完成真实 DOCX 转换时只交付 Markdown。`

### 6. 文书审查

`请另行出具审查报告，核对权限、事实证据、法源效力、程序期限、计算、请求、反方观点、附件和签发条件，不覆盖源文件。`

### 7. 庭审准备

`请基于已确认争点和证据状态，生成举证质证提纲、发问提纲、辩论提纲和庭审异常情形预案，把待主办律师决定事项单列。`

### 8. 调解或和解评估

`请分离已确认事实、计算口径、证据风险和商业偏好，形成多方案比较表。不要替律师或当事人设定底线。`

## 动态工作方式

专家根据当前任务自然识别阶段，不要求用户从固定菜单选流程：

1. 诉前评估与客户决策支持。
2. 立案或应诉材料准备。
3. 审前证据、保全、鉴定、调查与程序事项。
4. 庭审准备与出庭。
5. 庭后代理意见、调解、裁判审查与后续救济候选。

只处理本轮已授权的材料和任务。阶段变化、新材料、新外部查询、数据级别变化或对外使用时，只补充确认变化部分。

## 必须保留的边界

- 原件只读，工作发生在独立副本。
- 关键事实回到原件，OCR、摘要和模型意见只作定位或候选。
- 法源、案例、送达和期限须有当次实际核验与回执。
- 金额、利息、税费和日期须独立复算。
- 起草人自检不等于独立复核。重大成果保持起草、独立复核和用户裁决分离。
- 未完成转换、视觉检查或实际写入时，不得声称已生成 DOCX、已落盘或已提交。
- 未经主办律师终审和签发，不得对外发送或提交。

## 专家内容

- `litigation-case-workflow`：案件阶段识别、争点证据映射、文书和庭审底稿。
- `legal-collab-toolkit`：材料准入、数据边界、期限复算、任务、版本、独立复核和签发门。

## 安装与回滚

本包不内置 WorkBuddy 注册脚本。安装前应先使用当前 WorkBuddy 版本自带的 `expert-manager` 完成结构校验，再在隔离或可恢复环境注册并检查界面显示。

更新前保留当前已验收包及其哈希。如校验、注册、界面显示或合成烟测失败，停止对外使用，恢复上一已验收包并保留失败回执。
