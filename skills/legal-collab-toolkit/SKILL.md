# 法律协作工具包

> 适用于 2-3 人律师协作团队，覆盖文书互审、任务追踪、版本控制、数据安全四个核心协作场景。

## 一、文书互审规范

### 审查流程

1. **起草人提交**：起草人在文书文件名中标注版本号（如 `答辩状-v1.0.md`），通过任务系统分派给审查人
2. **审查人审查**：审查人按以下清单逐项检查，在文书末尾追加「审查意见」章节
3. **起草人修订**：根据审查意见修订，版本号升至 v1.1，回传审查人确认
4. **定稿确认**：审查人确认无异议后，文件名改为 `答辩状-定稿.md`，标注定稿日期

### 审查清单

| 维度 | 检查项 | 通过标准 |
|------|--------|----------|
| 事实准确性 | 文书中陈述的事实是否有证据支撑 | 每项事实标注证据编号 |
| 法源有效性 | 引用的法条是否现行有效 | 通过 MCP 工具核实（北大法宝/元典） |
| 逻辑完整性 | 论证链条是否闭合 | 事实→法律→结论三段论完整 |
| 格式规范 | 是否符合法院要求格式 | 标题、编号、落款齐全 |
| 数据脱敏 | 是否完成脱敏处理 | 当事人姓名、地址等按脱敏规则处理 |
| 语言表述 | 是否存在歧义或不当表述 | 长短句交替，无口语化表达 |

### 审查意见格式

```markdown
## 审查意见

**审查人**：[姓名]
**审查日期**：YYYY-MM-DD
**版本**：v1.0 → v1.1

### 修改建议

1. **[第X段] 事实表述问题**
   - 原文："[引用原文]"
   - 建议："[修改建议]"
   - 理由：[修改理由]

2. **[第X段] 法源核实**
   - 原文引用：[法条名称]
   - 核实结果：[已核实/需更新/已废止]
   - 来源：[北大法宝/元典，YYYY-MM-DD]

### 通过项
- [x] 事实准确性
- [x] 格式规范
- [ ] 法源有效性（需修订后重新核实）
```

## 二、任务追踪约定

### 任务生命周期

```
创建 → 分派 → 进行中 → 提交审查 → 审查中 → 修订 → 定稿 → 交付
                ↓                                        ↑
              阻塞 → 解决阻塞 ──────────────────────────────┘
```

### 任务创建规范

每次创建任务时必须包含：

| 字段 | 说明 | 示例 |
|------|------|------|
| 标题 | 动词+对象，简明扼要 | "起草买卖合同纠纷答辩状" |
| 负责人 | 执行人 | 主办律师/协办律师 |
| 截止日 | 绝对日期，不含模糊表述 | 2026-08-15 |
| 优先级 | 高/中/低 | 高（有法定期限） |
| 关联文件 | 任务涉及的文件路径 | `03_起诉阶段材料/答辩状-v1.0.md` |
| 交付物 | 预期输出 | "答辩状定稿版 .md + .docx" |

### 法定期限追踪

以下期限必须创建定时提醒：

| 期限类型 | 法定天数 | 起算点 |
|----------|----------|--------|
| 答辩期限 | 15日 | 收到起诉状副本之日 |
| 举证期限 | 不少于15日 | 收到受理通知书之日 |
| 上诉期限 | 判决15日/裁定10日 | 判决书送达之日 |
| 执行申请期限 | 2年 | 生效法律文书规定履行期届满之日 |
| 执行异议期限 | 10日 | 收到执行裁定书之日 |
| 案外人异议期限 | 15日 | 执行标的执行终结前 |

### 进度报告

每周生成一次进度简报，格式：

```markdown
## 案件进度周报 - [案件名称]

**报告周期**：YYYY-MM-DD 至 YYYY-MM-DD

### 本周完成
1. [任务名] - [完成人] - [交付物]
2. ...

### 进行中
1. [任务名] - [负责人] - [进度%] - [预计完成日]
2. ...

### 待办
1. [任务名] - [负责人] - [截止日]
2. ...

### 风险提示
- [期限预警/证据缺口/对方动态等]
```

## 三、版本控制规则

### 文件命名规范

```
[阶段]_[文书类型]-v[主版本].[次版本].[修订号].md
```

示例：
- `03_答辩状-v1.0.md`（初稿）
- `03_答辩状-v1.1.md`（审查后修订）
- `03_答辩状-定稿.md`（终稿）

### 版本号规则

| 版本号 | 含义 | 触发条件 |
|--------|------|----------|
| vX.0 | 初稿 | 首次完成 |
| vX.Y | 修订版 | 审查意见修订 |
| 定稿 | 终稿 | 审查人确认通过 |

### 变更记录

每次版本更新时，在文件末尾维护变更记录：

```markdown
## 变更记录

| 版本 | 日期 | 修改人 | 修改内容摘要 |
|------|------|--------|-------------|
| v1.0 | 2026-08-01 | 协办律师 | 初稿完成 |
| v1.1 | 2026-08-03 | 主办律师 | 第3段法源更新，第5段事实补充证据引用 |
| 定稿 | 2026-08-05 | 协办律师 | 审查通过，定稿 |
```

## 四、数据安全分级

### 四级分类标准

| 级别 | 定义 | 处理要求 | 示例 |
|------|------|----------|------|
| **绿级** | 已公开信息 | 可自由使用 | 公开裁判文书、已发布法规 |
| **黄级** | 一般案件信息 | 脱敏后可上云 | 案件名称（脱敏）、诉讼请求、法律分析 |
| **红级** | 敏感案件信息 | 硬性不上云，仅本地处理 | 当事人身份信息、证据原件、商业秘密 |
| **红线** | 极敏感信息 | 禁止任何 AI 处理 | 国家秘密、未成年人信息、特定行业保密事项 |

### 脱敏规则

| 信息类型 | 脱敏方式 | 示例 |
|----------|----------|------|
| 自然人姓名 | 姓+某某 | 张某某 |
| 企业名称 | 行业+某公司 | 某设备公司 |
| 身份证号 | 保留前6后4 | 370100********1234 |
| 银行账号 | 保留后4位 | ****1234 |
| 地址 | 保留到区 | 某市某区 |
| 电话 | 保留前3后2 | 138****56 |

### 上传审批流程

1. 文件上云前由主办律师确认密级
2. 黄级文件脱敏后上云，标注「脱敏-黄级」
3. 红级文件禁止上云，仅本地处理
4. 每次上云操作记录文件名、密级、操作人、时间
