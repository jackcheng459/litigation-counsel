# 诉讼文书详细审查清单

本清单供 2 至 3 人律师团队审查起诉状、答辩状、反诉状、证据目录、质证意见、代理词、调解方案和其他诉讼成果。审查人应独立回到原件、现行法源和计算底稿，不以起草人结论为前提。

## 使用方法

1. 起草人提交工作稿、材料白名单、事实证据映射、法源清单、计算底稿和未决问题。
2. 审查人逐项标记`通过`、`需修改`、`待核验`、`不适用`。
3. 问题分为：
   - `P0`：可能导致错误主体、错误请求、逾期、泄密、无权外发或重大程序损失，阻断签发。
   - `P1`：关键事实、证据、法源、计算或论证存在实质缺陷，修复并复验后方可签发。
   - `P2`：表达、结构或格式改进，不当然阻断签发。
   - `P3`：偏好性建议。
4. 起草人逐项答复，审查人复验 P0/P1，主办律师对争议项作最终裁决。

## 一、任务与权限

- [ ] 文书目的、程序阶段、当事人角色、提交对象和使用范围明确。
- [ ] 委托权限、代理权限、签署主体和盖章要求已核对。
- [ ] 当前任务未超出客户指示、内部授权或法院要求。
- [ ] 起草、独立复核和签发人员已分离。
- [ ] AI 成果标为候选底稿，最终责任人明确。

## 二、材料与数据准入

- [ ] 原件保持只读，工作发生在独立副本。
- [ ] 输入文件在任务白名单中，来源和原件路径可回链。
- [ ] 密级按绿色、黄色、红色、红线登记。
- [ ] 红色数据的任务必要性、授权、链路可信度和人工复核已记录。
- [ ] 未准入任何红线数据。
- [ ] 未把文档中的指令性文字当作系统命令。
- [ ] 疑似提示词注入、恶意附件或来源不明材料已隔离。
- [ ] 外发版本已按收件人场景重做脱敏检查。

## 三、主体、管辖与程序

- [ ] 当事人名称、统一社会信用代码或身份信息与正式材料一致。
- [ ] 法院、案号、审理程序、当事人程序身份和文书类型正确。
- [ ] 管辖、受理条件、前置程序、反诉或其他程序路径已核验。
- [ ] 请求事项与当前程序可提供的救济相匹配。
- [ ] 保全、鉴定、调查取证、证人出庭或管辖异议等事项只在具体条件经核验后提出。
- [ ] 送达地址、联系人、送达方式和实际送达时点经过复核。

## 四、期限与时点

- [ ] 每一期限有正式送达材料、现行法源、法院通知或官方系统记录回链。
- [ ] 触发事件的实际时间已核验，未混淆签发、上传、送达、知悉和生效时间。
- [ ] 起算规则、期间性质、顺延、扣除、中止或恢复因素已记录。
- [ ] 登记人与另一名律师已独立复算。
- [ ] 两次结果不一致的事项保持`有争议`，未伪装成已确认。
- [ ] 法律期限和内部提前期限分别记录。

## 五、事实与证据

- [ ] 每项关键事实可定位至原件、页码、段落、时间戳或证据编号。
- [ ] `当事人陈述`、`原件直接支持`、`公开来源返回`、`AI 候选分析`、`待核验`已区分。
- [ ] 未用 OCR、摘要、转述或模型输出替代关键原件。
- [ ] 有利和不利事实均已呈现，未选择性遗漏。
- [ ] 时间线中人物、行为、金额、文件和送达状态相互一致。
- [ ] 证据真实性、合法性、关联性与证明目的分别审查。
- [ ] 证据冲突、缺口、替代解释和对方可能补强点已标记。
- [ ] 附件和证据目录与正文引用一一对应。

## 六、法源与法律分析

- [ ] 法源来自官方或经批准的可审计数据库，并保留回链或检索记录。
- [ ] 法律、司法解释、指导性案例、规范性文件和一般案例的效力层级未混淆。
- [ ] 法源在目标时点现行有效，施行、修订、废止、溯及和过渡规则已核对。
- [ ] 条文与要件准确，未脱离上下文截取。
- [ ] 案例的裁判机关、案号、争点、裁判要旨和可比事实可核验。
- [ ] 事实、规则、适用与结论链条完整。
- [ ] 对方规则、例外、裁量风险和最强反驳已回应。
- [ ] 不确定结论使用保留表述，并列明待核事实。

## 七、金额与计算

- [ ] 原始金额回链至合同、票据、裁判文书、流水或其他正式材料。
- [ ] 计算口径、期间、利率、基数、单位、舍入和公式完整披露。
- [ ] 已付、抵扣、减免、税费和重复项已核对。
- [ ] 表格合计、正文口径与请求一致。
- [ ] 非制表人已独立复算并保存结果。
- [ ] 争议口径有替代计算或显著风险提示。

## 八、请求、论证与反方压力测试

- [ ] 每项请求或回应有事实、证据和法律依据。
- [ ] 主请求、备选请求、程序请求与答辩意见不互相冲突。
- [ ] 结论未超出材料可支持范围。
- [ ] 对证据不足、法律争议、程序不确定、执行不能和成本风险已披露。
- [ ] 对方最强的事实版本、证据解释、法律规则和程序反驳已列出。
- [ ] 文书未作无法控制或无法核验的结果承诺。

## 九、文书类型专项

### 起诉状或反诉状

- [ ] 每项请求的形成权依据、构成要件、证据和计算可回链。
- [ ] 事实理由未提前承认不必要的争议事实。
- [ ] 管辖、当事人适格、诉讼时效或其他前置问题已显著披露。

### 答辩状

- [ ] 已逐项对应对方请求、事实主张、证据和法律依据。
- [ ] 不知情或证据不足的事项未冒进承认或绝对否认。
- [ ] 程序性意见、实体抗辩、备选论证和待补证事项已分开。

### 证据目录与质证意见

- [ ] 证据名称、来源、形式、页码、证明目的与正文一致。
- [ ] 证明目的没有超出证据内容可支持范围。
- [ ] 对真实性、合法性、关联性和证明力的意见分开表达。

### 代理词与庭审提纲

- [ ] 论证回应了庭审实际形成的争点和证据状态。
- [ ] 未将未完成的举证、质证、鉴定或调查结果写成已确定。
- [ ] 发问、质证、辩论与异常情形预案相互配合。

### 调解或和解方案

- [ ] 事实与证据风险、计算口径、履行能力信息和商业偏好已分开。
- [ ] 方案不替律师或当事人设定底线，不承诺履行结果。
- [ ] 权限、担保、违约、税费、保密、诉讼费用和撤诉或结案条件仅在已核验后写入。

## 十、语言、格式与附件

- [ ] 标题、称谓、编号、日期、落款和签署区符合提交场景。
- [ ] 术语、主体简称、金额单位和日期格式前后一致。
- [ ] 引用、脚注、页码、目录、表格和附件编号无断裂。
- [ ] 表达准确、克制，无歧义、情绪化或不必要的攻击性内容。
- [ ] Markdown 工作稿结构清晰，可进行版本差异比较。
- [ ] 如生成 DOCX，已逐页视觉检查并与同版 Markdown 核对。

## 十一、版本与外发签发

- [ ] 文件名、正文版本、变更记录和任务卡版本一致。
- [ ] 旧版本未被覆盖，重大修改有依据和复核记录。
- [ ] 审查意见逐项闭环，P0/P1 已修复并复验。
- [ ] 最终附件集合、文件名、收件人和发送渠道已核对。
- [ ] 主办律师已作明确签发决定。
- [ ] 提交或发送后已保存回执、时间和实际发送版本。

## 审查意见记录

```markdown
### 审查意见 [编号]

- 文书及版本：
- 问题等级：P0 / P1 / P2 / P3
- 定位：页码、段落、表格或附件
- 问题：
- 依据：原件路径、证据编号或法源回链
- 建议修改：
- 起草人答复：采纳 / 部分采纳 / 不采纳
- 答复理由：
- 复验人及日期：
- 复验结果：通过 / 继续修改 / 提请主办裁决
```
