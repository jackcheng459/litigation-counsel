# 证据与争点矩阵

本文件用于建立争点、要件、事实、证据、法源与对方反驳之间的可审计映射。矩阵是工作底稿，不是法院已认定的事实或律师最终策略。

## 一、来源状态

| 状态 | 定义 | 不得越界 |
|---|---|---|
| 原件直接支持 | 可定位至正式材料的页码、段落、时间戳或证据编号 | 不得超出文件内容和证明范围 |
| 当事人陈述 | 当事人或客户提供但尚未被充分材料支持 | 不得写成已查明事实 |
| 公开来源返回 | 本轮实际查询并保留对象、字段、时间和回链 | 不得写成法院或对方已确认 |
| AI 候选分析 | 从已知材料推导的争点、解释、风险或动作 | 不得进入“已证实”或“已核验法源” |
| 待核验 | 尚缺原件、法源、程序回执、查询回执或律师确认 | 不得猜测补齐 |

请求尚未由律师确认时，标题中保留“候选”。不得为了形式完整而增加没有事实触发的请求或抗辩。

```markdown

| 证据编号 | 证据名称 | 来源/取得方式 | 形式与原件状态 | 实际读取范围 | 拟证明目的 | 能证明 | 不能证明 | 真实性 | 合法性 | 关联性 | 冲突/缺口 | 补强动作 |
|---|---|---|---|---|---|---|---|---|---|---|---|---|
| E-001 |  |  |  |  |  |  |  | 待核 | 待核 | 待核 |  |  |
```

视频、录音、聊天记录、扫描件、电子数据导出或网页存证还应单列完整性、时间、账号归属、导出方式、原始载体、校验值和补强证据待核项。

## 五、争点矩阵

```markdown
# 争点矩阵

| 争点编号 | 争点 | 我方候选结论 | 我方最强依据 | 对方最强观点 | 对方可能证据 | 我方回应 | 无法回应点 | 法源状态 | 下一核验动作 | 律师决定 |
|---|---|---|---|---|---|---|---|---|---|---|
| I-001 |  |  |  |  |  |  |  | 已核验/待核验 |  | 待决定 |
```

争点应来自当事人主张、案件材料、程序文书或庭审实际形成的问题。不得仅因某类案件通常有某争点就将其写成本案已有争点。

```markdown
|---|---|---|---|---|---|---|---|---|---|---|
| G-001 |  |  |  |  |  |  |  |  |  |  |
```

下一动作必须合法、必要且与具体缺口对应。不得把外部查询、调查取证、保全、鉴定或其他程序动作写成已完成，除非存在实际回执。

## 七、增量更新

收到新材料时，不重写整份底板。先生成：

```markdown
# 证据矩阵增量更新 [批次]

| 新材料 | 实际读取范围 | 影响的事实/证据/争点编号 | 原状态 | 新状态 | 变化理由 | 不变事项 | 新缺口 | 律师复核 |
|---|---|---|---|---|---|---|---|---|
|  |  |  |  |  |  |  |  | 待复核 |
```

没有被新材料支持或改变的事项保持原状态，不顺带改写。
