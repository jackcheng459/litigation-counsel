# 诉讼案件工作流

根据用户当前任务和正式程序材料识别阶段，只展开与当前交付有关的流程。不要把诉前、起诉或应诉、审前、庭审、庭后写成每次必须从头执行的线性任务。

## 一、入口确认

首先确认：

1. 当事人角色：原告、被告、反诉人、第三人或待确认。
2. 程序阶段：诉前、已立案、已应诉、审前、庭审中、庭后、已裁判或待确认。
3. 任务类型：分析、证据整理、法源核验、文书起草、文书审查、庭审准备、调解评估或其他。
4. 授权材料和输出范围。
5. 是否需要外部检索、文件转换、写入工作区或对外使用。

无法确认阶段时，保持`待确认阶段`。仍可整理用户直接提供的文字，但不得以阶段不明为由猜测程序状态或期限。

详细路由见 [案件阶段路由](references/case-stage-router.md)。

## 二、建立事实底板

任何策略或文书前，先建立最小事实底板：

- 当事人与程序身份；
- 用户目标与限制；
- 已授权材料及实际读取范围；
- 时间线；
- 请求或对方请求；
- 关键事实、来源状态与定位；
- 待核事项、材料缺口和冲突；
- 程序文书、送达、期限、金额和法源状态。

事实状态只使用：`原件直接支持`、`当事人陈述`、`公开来源返回`、`AI 候选分析`、`待核验`。

证据、争点与要件的具体映射使用 [证据与争点矩阵](references/evidence-and-issue-matrix.md)。

## 三、原告方诉前或起诉分支

只有当用户站在原告、申请人或拟主张权利一方时展开：

1. 明确客户实际目标、可接受替代方案与时间成本约束。
2. 核对主体、请求对象、权利基础、管辖、前置程序和时间效力待核项。
3. 将每项候选请求拆为要件，映射事实、证据、法源和缺口。
4. 列出对方最强事实版本、程序抗辩、实体抗辩和证据攻击。
5. 评估证据保全、财产保全、调查取证、鉴定或其他程序措施的候选条件，不得无事实触发就批量展开。
6. 形成诉前评估或起诉材料工作稿，决策状态保持“待律师决定”。

不得输出胜诉率、保全成功率或结果承诺。

## 四、被告方应诉分支

只有当用户站在被告、被申请人或需要回应主张一方时展开：

1. 逐项提取对方请求、事实主张、证据、法律依据和程序主张。
2. 将我方信息分为确认、争议、不知情、待核验和需要补证。
3. 检查管辖、主体、时间效力、前置程序、请求范围和代理权限待核项。
4. 建立“对方要件与证据、我方回应、反证或反方案、对方可能补强”矩阵。
5. 区分程序意见、实体抗辩、备选论证、反诉或其他候选动作。
6. 形成答辩策略、证据补强和文书工作稿，对未掌握事实不冒进承认或绝对否认。

## 五、审前管理分支

已进入诉讼且当前任务涉及证据、送达、保全、鉴定、调查取证、证人出庭、举证或其他审前事项时展开：

- 用正式程序文书和送达证据更新阶段与期限登记。
- 按争点和要件更新证据矩阵，不为新材料顺带改写未受影响事项。
- 对新证据记录实际读取范围、能证明与不能证明、冲突、补强与对方反应。
- 每项程序动作列明触发事实、法源状态、所需材料、期限状态、责任人和回执。
- 缺少法源、送达、授权或关键材料时，状态保持`阻塞`。

## 六、庭审准备分支

庭审准备以已确认争点、当前证据状态和未决事项为输入，默认交付：

1. 庭审目标与争点清单。
2. 举证与证明目的核对表。
3. 对方证据的质证维度与待核事项。
4. 发问提纲，每个问题标注目标与可能风险。
5. 辩论提纲，包含我方主线、对方最强反驳与回应。
6. 庭审异常情形预案，如新证据、请求变更、程序争议或调解提议，仅列候选响应和待主办决定事项。

不得预设法庭已接受某证据、某争点已确定或某申请已获准。

## 七、庭后、调解与裁判处理

根据实际庭审笔录、调解沟通或裁判原件展开：

- 庭后意见只回应庭审实际形成的争点、证据状态和法庭要求。
- 调解或和解分开已确认事实、计算口径、证据风险、履行条件和商业偏好，只生成多方案比较。
- 不替律师或当事人设定调解底线、承诺履行或作处分性表示。
- 裁判审查先提取主文、认定事实、证据采信、裁判理由、费用负担、送达与救济告知，再形成候选复核问题。
- 后续救济或执行衔接须重新核验程序身份、裁判类型、送达、生效、法源和用户授权，不从当前阶段自动跳转。

## 八、文书产出

在完成对应的事实证据映射、法源状态和未决问题后，使用 [诉讼文书模板](references/litigation-document-templates.md) 生成工作稿。

工作稿须：

- 标明案件代号、程序阶段、当事人角色、版本与状态；
- 事实与证据可回链，待核事项显著标记；
- 法源列明实际核验状态；
- 将请求、策略、和解、程序动作与签发事项保留给律师；
- 单列对方最强观点、当前无法回应事项与下一步核验。

## 九、法源核验

每次具体使用法源时，按 [法源与程序核验](references/official-source-verification.md) 记录规范、条文、效力、时间效力、个案事实对应和回链。

不得使用历史课件、旧案底稿或模型记忆作为现行法源回执。无法核验时，状态保持`待核验`。

## 十、完成条件

只有当下列项目均有证据时，才能报告为已完成：

1. 交付物已真实生成，可回读且路径明确。
2. 关键事实、证据、法源、期限和计算状态如实披露。
3. 文书已通过起草人自检，但独立复核状态另行记录。
4. 如生成 DOCX，已真实转换、打开并逐页检查。
5. 如实际写入工作区，已回读文件并记录路径。
6. 如已外发或提交，已有主办律师签发与实际回执。

没有证据时，仅能报告为候选草稿、建议更新、待复核、待签发或阻塞。
